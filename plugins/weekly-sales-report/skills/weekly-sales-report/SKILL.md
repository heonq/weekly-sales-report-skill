# 주간 매출 리포트 → 슬랙 전송

구글 시트 `판매관리`의 판매 데이터로 **지난주(월~일)** 매출 리포트를 만들고, 슬랙 채널에 제목 메시지 1개 + 스레드 댓글 1개로 보낸다.

## 고정 기준

| 항목 | 값 |
|---|---|
| 데이터 | 구글 시트 `판매관리` → `판매내역` 시트 |
| 대상 기간 | 실행일 기준 지난주 월요일~일요일 |
| 비교 기간 | 그 전주 월요일~일요일 |
| 매출 기준 | `결제금액`만 합산 (배송비 제외) |
| 슬랙 채널 | `#주간리포트-테스트` (`slack_search_channels`로 channel_id 조회) |
| 스레드 형식 | 댓글 하나에 리포트 전체 |

사용자가 다른 기간·채널·기준을 말하면 그 값을 따른다.

## 시트 구조 (`판매내역`)

열: `주문일 | 주문번호 | 판매채널 | 카테고리 | 상품명 | 옵션 | 수량 | 판매단가 | 결제금액 | 배송비`

- 주문일은 `YYYY-MM-DD` 문자열, 날짜 오름차순으로 쌓여 있다.
- 금액은 `33,300`처럼 쉼표가 들어간 문자열이므로 숫자로 바꿔서 계산한다.
- 한 주문번호에 여러 행(상품)이 있을 수 있다. **주문 수 = 고유 주문번호 개수**.
- 데이터가 8,000행 가까이 되므로 A열 전체를 한 번에 읽지 않는다 (출력이 잘린다).

## 절차

### 1. 날짜 계산
`current_time` 도구로 오늘 날짜를 확인하고 지난주 월~일, 전주 월~일을 구한다.
제목 형식: `[주간 매출 리포트] M/D(월)~M/D(일)` — 예: `[주간 매출 리포트] 10/19(월)~10/25(일)`

### 2. 중복 확인 (전송 전 필수)
`slack_read_channel`로 채널 최근 메시지를 읽는다. 1단계의 제목과 **첫 줄이 같은 메시지가 있으면 아무것도 보내지 않고** 사용자에게 이미 전송됐다고 알린 뒤 종료한다.

### 3. 데이터 가져오기
1. `Google_Drive__search_files`로 `title contains '판매관리'` + 스프레드시트 mimeType 검색 → spreadsheetId 확보.
2. `get_spreadsheet`(fields: `sheets.properties`)로 행 수 확인.
3. 마지막 행 근처부터 작은 범위(`판매내역!A{n}:A{n+5}`)를 찍어 보며 대상 기간 시작일(전주 월요일) 위치를 좁힌다. 하루 평균 약 15행.
4. 전주 월요일 ~ 지난주 일요일을 포함하는 범위를 `A:J`로 한 번에 가져온다. 범위 앞뒤에 다른 날짜가 섞여도 3단계 계산에서 날짜로 거른다.

### 4. 집계 (Python으로 계산)
가져온 행을 스크래치패드의 파일로 저장하고 Python으로 계산한다. 숫자를 머리로 더하지 않는다.

두 기간 각각:
- 총매출(결제금액 합), 주문 수(고유 주문번호), 판매 수량(수량 합), 객단가(총매출 ÷ 주문 수)
- 판매채널별 매출·비중
- 카테고리별 매출·비중
- 상품명별 매출·수량 (TOP 5)

증감률 = (이번 주 ÷ 전주 − 1) × 100, 소수 첫째 자리. 상승은 `▲`, 하락은 `▼`.

### 5. 슬랙 전송
1. 2단계 중복 확인을 **전송 직전에 한 번 더** 수행한다.
2. 채널에 제목 한 줄만 보낸다 → 응답의 `message_ts` 확보.
3. 같은 채널에 `thread_ts = message_ts`로 아래 템플릿의 리포트를 댓글 하나로 보낸다.

### 6. 완료 보고
사용자에게 전송 완료, 메시지 링크, 핵심 수치 2~3줄(총매출 증감, 눈에 띄는 채널·카테고리 변화)을 알린다.

## 주의
- 대상 주의 데이터가 시트에 아직 없거나 일부만 있으면 전송하지 말고 사용자에게 알린다.
- 전주에 없던 채널·카테고리는 전주 대비를 `신규`로 표기한다.
- 원본 시트는 읽기만 하고 수정하지 않는다.
